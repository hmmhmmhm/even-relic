# G2 점진식 이미지 그리드 진단 설계

## 배경

`hud400-text3s` 빌드에서 텍스트 전용 시작 페이지는 실제 G2에 표시되었다.
3초 뒤 텍스트 컨테이너 1개와 이미지 컨테이너 4개로 페이지 전체를 바꾸는
`rebuildPageContainer()`는 `false`를 반환했다. 실패는 PNG 로드와
`updateImageRawData()` 호출보다 먼저 발생했으므로, 이미지 파일이나 전송 간격이
현재 실패의 직접 원인은 아니다.

다음 진단은 페이지에 포함되는 이미지 컨테이너 수를 한 번에 하나씩 늘려,
최초로 실패하는 컨테이너 수와 호출 경계를 확인한다.

## 검토한 접근

### 선택: 누적식 1→2→3→4 컨테이너

첫 시작 페이지에는 로딩 텍스트와 TL 이미지 컨테이너 하나만 포함한다. 이후
페이지를 이미지 2개, 3개, 4개 구성으로 차례로 재구성한다. 재구성은 페이지 전체를
교체할 수 있으므로, 각 단계에서 현재 단계에 포함된 타일을 모두 다시 전송한다.

장점은 컨테이너 수별 성공 여부를 한 번의 실행에서 확인하고, 성공한 각 단계의
완성된 이미지를 안경으로 볼 수 있다는 점이다. 전송 횟수는
`1 + 2 + 3 + 4 = 10`회로 늘어난다.

### 제외: 이미지 컨테이너 4개를 처음부터 생성

페이지 재구성을 피하고 네 이미지를 1초 간격으로 전송할 수 있지만, 컨테이너 수와
재구성 중 어느 조건이 실패 원인인지 분리하지 못한다.

### 제외: 매번 이미지 컨테이너 하나만 교체

각 PNG의 독립 전송 성공 여부는 확인할 수 있지만, 최종 400×200 그리드 구성을
검증하지 못한다.

## 호출 순서

1. Even Hub 브리지를 기다린다.
2. 로딩 텍스트와 TL 이미지 컨테이너로 시작 페이지를 생성한다.
3. 시작 페이지 생성이 성공한 경우에만 3초를 기다린다.
4. 이벤트 레이어의 로딩 문구를 공백으로 업데이트하고 결과를 기록한다.
5. TL 이미지를 전송하고 1초를 기다린다.
6. 텍스트와 TL·TR 컨테이너로 페이지를 재구성한다.
7. 재구성이 성공하면 TL과 TR을 직렬 전송하며 각 전송 뒤 1초를 기다린다.
8. 같은 방식으로 3개 이미지 페이지와 4개 이미지 페이지를 차례로 재구성한다.
9. 네 이미지가 모두 전송되면 완료 상태를 기록한다.

`updateImageRawData()`는 동시에 호출하지 않고 항상 앞선 호출이 끝난 뒤 호출한다.

## 페이지 구성

- 텍스트 이벤트 레이어: ID 1, `576×288`, 이벤트 캡처 활성
- TL: ID 2, `(88, 44)`, `200×100`
- TR: ID 3, `(288, 44)`, `200×100`
- BL: ID 4, `(88, 144)`, `200×100`
- BR: ID 5, `(288, 144)`, `200×100`

시작 페이지의 텍스트는 `RELIC HUD LOADING...`이다. 이미지 전송 단계에서는
이벤트 레이어의 내용으로 공백을 사용한다. 시작 페이지의 3초 대기가 끝나면
`textContainerUpgrade()`로 문구를 공백으로 바꾼다. 이 업데이트가 실패하더라도
결과만 기록하고 이미지 전송 진단은 계속한다.

## 로그와 실패 처리

각 단계는 다음 경계를 웹뷰에 순서대로 기록한다.

- `STAGE 1 STARTUP RESULT: <result>`
- `STAGE 1 LOADING CLEAR RESULT: true|false`
- `STAGE 1 relicTL RESULT: <result>`
- `STAGE 1 WAIT 1S COMPLETE`
- `STAGE 2 REBUILD RESULT: true|false`
- `STAGE 2 relicTL RESULT: <result>`
- `STAGE 2 relicTR RESULT: <result>`
- 같은 형식의 STAGE 3·4 로그

시작 페이지 생성, 페이지 재구성, 이미지 전송 중 하나라도 실패하면 다음 단계로
넘어가지 않는다. 마지막으로 성공한 단계의 화면과 로그를 유지해 실패 경계를
확인할 수 있게 한다.

## 테스트

- 시작 페이지가 텍스트 1개와 이미지 1개로 구성되는지 검사한다.
- 단계별 이미지 컨테이너 수가 1, 2, 3, 4로 증가하는지 검사한다.
- 호출 순서가 `create → 3초 → send → 1초 → rebuild → send`를 따르는지 검사한다.
- 각 재구성 뒤 현재 단계의 모든 이미지를 직렬 재전송하는지 검사한다.
- 특정 단계의 재구성이 `false`이면 추가 로드와 전송이 없는지 검사한다.
- 특정 이미지 전송이 실패하면 이후 이미지와 단계가 실행되지 않는지 검사한다.

## 성공 기준

- 자동 테스트, TypeScript 검사와 프로덕션 빌드가 통과한다.
- Tailscale의 4180 정적 서버가 새 진단 빌드를 제공한다.
- 실제 G2에서 STAGE 1 이미지가 표시된다.
- STAGE 2·3·4 가운데 최초로 실패하는 재구성 단계 또는 네 단계의 성공을
  웹뷰 로그로 식별할 수 있다.
