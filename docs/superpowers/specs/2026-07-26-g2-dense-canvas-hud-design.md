# G2 고밀도 Canvas HUD 설계

## 목표

기존 RELIC HUD의 시간, 위치, 나침반, 지도, 마이크, 가속도, 경로 안내와
퀘스트 구성을 유지하면서 원본 PNG 없이 `576×288` Canvas에 직접 다시
그린다. 교정 테스트에서 확인한 최대 외곽 안에서 요소와 글자를 키우고 검정
여백을 줄여 시스템 대시보드와 비슷한 크기로 체감되는 HUD를 만든다.

## 성공 기준

- `/hud-canvas`가 이미지 원본을 읽지 않고 Canvas 프리미티브와 문자만
  사용한다.
- 논리 화면은 정확히 `576×288`이다.
- 지도, 중앙 안내와 우측 센서 패널이 기존 시안보다 넓은 면적을 점유한다.
- 기존 `/`, `/diagnostic-v10`, `/calibration-max` 동작을 변경하지 않는다.
- SDK `0.0.10`의 네 이미지 컨테이너 직렬 전송 경로를 재사용한다.
- 실제 G2에서 네 타일이 표시되고 HUD 요소가 기존 이미지 시안보다 크게
  느껴지는지 사용자가 비교할 수 있다.

## 렌더링 구조

새 `src/canvas-hud.ts`가 렌더링을 전담한다. 이 모듈은 Even Hub 브리지나
React에 의존하지 않고 `HTMLCanvasElement` 하나만 입력받는다.

`App.tsx`는 `/hud-canvas` 경로에서 새 렌더러를 호출한다. 렌더링이 끝나면
기존 `transmitCanvas()`가 Canvas를 `288×144` 네 장으로 나누고
`relicTL`, `relicTR`, `relicBL`, `relicBR` 순서로 전송한다.

## 시각 원칙

- 배경은 완전한 검정으로 두어 실제 환경이 비치게 한다.
- 최대 밝기, 중간 밝기, 낮은 밝기의 세 단계만 사용한다.
- G2에서 녹색 계층으로 변환되는 것을 전제로 Canvas에서는 각각
  `#ffffff`, `#aaaaaa`, `#555555`를 사용한다.
- 모든 패널과 선은 정수 좌표의 `fillRect`와 1픽셀 경로로 그린다.
- 문자는 고정폭 글꼴을 사용하며 핵심 정보는 16~26픽셀, 보조 정보는
  10~13픽셀로 그린다.
- 기존 시안의 주변부 정보 구조는 유지하되 중앙 경로 안내를 키워 빈 공간을
  줄인다.

## 고정 레이아웃

| 영역 | 좌표와 크기 | 내용 |
|---|---|---|
| 시간·위치 | `8,8,132×54` | `14:37`, `HONGDAE` |
| 나침반 | `148,8,276×54` | 눈금, `N`, `NE 047°`, `E` |
| 링크 장식 | `432,8,136×54` | 우측 상단 프레임과 신호 막대 |
| 지도 | `8,72,184×172` | 도로망, 강조 경로, 현재 위치 화살표 |
| 지도 범례 | `8,252,184×28` | 축척과 목적지 표시 |
| 중앙 안내 | `204,72,188×130` | 큰 우회전 화살표, `NEXT 120m`, `우회전` |
| 하단 안내 | `204,214,188×66` | `다음 교차로에서 우회전` |
| 마이크 | `404,72,164×62` | `-24 dBFS`, 레벨 막대 |
| 가속도 | `404,142,164×80` | `X +0.12`, `Y -0.03`, `Z +0.98` |
| 퀘스트·뉴스 | `404,230,164×50` | `Q. 지하철역으로 이동`, `NEWS 02` |

패널 사이에는 최소 8픽셀 간격을 유지한다. 모든 영역은 Canvas 외곽과
4픽셀 이상의 안전거리를 둔다.

## 지도와 방향 표시

지도는 단순한 장식 이미지가 아니라 Canvas 선분으로 그린다.

- 낮은 밝기의 수평·수직·대각선 도로를 반복 배치한다.
- 최대 밝기의 경로는 세 구간의 굵은 선으로 표시한다.
- 현재 위치는 위쪽을 향한 채운 삼각형으로 표시한다.
- 목적지는 작은 사각 표식으로 표시한다.

중앙 안내는 오른쪽으로 꺾이는 굵은 화살표를 사용한다. 경로 안내 글자는
기존 하단 한 줄보다 크게 표시하고, 거리와 동작을 두 단계로 나눈다.

## 오류 처리

2D Canvas 컨텍스트를 얻지 못하면 기존 렌더러와 동일하게 명시적 오류를
던진다. 페이지 생성이나 개별 타일 전송 오류는 기존 상태 출력과
`transmitCanvas()` 오류 처리를 그대로 사용한다. 자동 재시도나 SDK 변경은
추가하지 않는다.

## 자동 검증

- 렌더러가 Canvas를 `576×288`로 설정하는지 검사한다.
- 주요 패널의 테두리 좌표와 세 밝기 팔레트를 검사한다.
- 지도 경로와 중앙 우회전 화살표가 그려지는지 검사한다.
- 핵심 문자와 고정 목업 값이 모두 렌더링되는지 검사한다.
- `/hud-canvas`가 새 렌더러와 네 이미지 컨테이너를 선택하는지 검사한다.
- 기존 루트와 세 진단 경로의 테스트가 계속 통과하는지 검사한다.
- 타입 검사, 프로덕션 빌드와 Sites 패키징 테스트를 실행한다.

## 하드웨어 판정

Even 앱 개발자 QR 스캐너로 `/hud-canvas`를 열어 네 타일 전송을 기다린다.
기존 이미지 HUD와 비교해 다음을 기록한다.

- 시간·나침반·지도·센서 글자가 더 크게 읽히는가?
- 중앙 안내가 시야를 과하게 막지 않으면서 화면을 더 크게 느끼게 하는가?
- 네 타일 경계에서 선이나 문자가 끊기지 않는가?
- 시스템 대시보드와 비교할 때 전체 정보 밀도가 충분한가?
