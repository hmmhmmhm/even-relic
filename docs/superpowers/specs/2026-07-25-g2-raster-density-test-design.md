# RELIC G2 래스터 정보 밀도 테스트 설계

작성일: 2026-07-25  
상태: 대화에서 승인된 첫 실기기 테스트 설계

## 목적

실제 G2 광학계에서 `Peripheral Focus` HUD의 글자 크기, 정보량, 대비,
주변부 배치와 중앙 시야 확보 정도를 빠르게 확인한다. 이번 단계에서는
실시간 데이터나 네이티브 Text 스타일을 평가하지 않는다.

## 범위

- 선택한 HUD 시안을 576 x 288 Canvas 한 장으로 렌더링한다.
- Canvas를 288 x 144 크기의 네 분면 PNG로 인코딩한다.
- Even Hub SDK로 이미지를 순차 전송한다.
- SDK가 요구하는 이벤트 캡처 Text는 공백으로 둔다.
- 더블 탭 종료만 연결한다.

지도, 위치, 시간, STT, 음량, IMU, 퀘스트와 뉴스는 모두 이미지 속
고정 목업이다. 센서, 마이크, 네트워크와 저장 기능은 연결하지 않는다.

## 구성 요소

### Canvas 미리보기

선택한 원본 시안을 브라우저에서 576 x 288로 축소한다. 휴대폰과 PC
미리보기는 안경으로 전송할 동일한 Canvas를 표시한다.

### 타일 인코더

좌상, 우상, 좌하, 우하 순서로 네 타일을 만든다. 각 타일은 G2 Image
컨테이너 최대 크기인 288 x 144를 사용한다.

### 안경 전송기

전체 화면 공백 Text 이벤트 레이어 하나와 Image 컨테이너 네 개로 시작
페이지를 만든다. 이미지 업데이트는 BLE 충돌을 피하도록 한 번에 하나씩
기다려 전송한다. 한 타일이라도 실패하면 어느 타일에서 실패했는지 휴대폰
상태 문구로 알린다.

## 실행 흐름

1. WebView가 HUD 원본을 Canvas에 그린다.
2. Even 앱 브리지가 준비될 때까지 기다린다.
3. 5개 컨테이너로 시작 페이지를 생성한다.
4. Canvas를 네 PNG로 인코딩한다.
5. 네 PNG를 좌상단부터 순차 전송한다.
6. 휴대폰에 완료 상태를 표시한다.

Safari에는 Even 앱 브리지가 없으므로 Canvas 미리보기만 보인다. 실제
안경 테스트는 Even 앱 개발자 영역의 QR 사이드로드로 실행한다.

## 오류 처리

- Canvas 2D Context 또는 PNG 인코딩이 없으면 명시적 오류를 표시한다.
- 시작 페이지 생성 결과가 성공이 아니면 이미지 전송을 시작하지 않는다.
- 이미지 결과를 SDK 정규화 함수로 판정하고 실패한 타일 이름을 표시한다.
- BLE 이미지 호출은 병렬 실행하지 않는다.

## 검증 기준

- Canvas 논리 크기가 정확히 576 x 288이다.
- Image 타일 네 장이 빈틈없이 전체 화면을 덮는다.
- 보이는 네이티브 Text가 없다.
- 시작 페이지 생성 뒤 ID 2, 3, 4, 5 순서로 이미지를 보낸다.
- 단위 테스트, TypeScript 검사와 프로덕션 빌드가 성공한다.
- 최종 시각 평가는 사용자가 실제 G2에서 확인한 뒤 확정한다.
