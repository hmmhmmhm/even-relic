# G2 최대 표시 영역 교정 테스트 설계

## 목표

Even Hub 플러그인의 `576×288` 최대 좌표 영역과 G2 시스템 대시보드의
체감 외곽을 실제 안경에서 비교한다. 이번 테스트는 RELIC 시안의 콘텐츠
크기가 아니라 플러그인 표시 영역 자체가 대시보드보다 작은지 판별한다.

## 판별 범위

이 테스트는 다음 질문에 답한다.

- 플러그인의 가장 바깥쪽 픽셀이 실제로 어디까지 보이는가?
- 네 개의 `288×144` 이미지 타일이 경계와 중앙에서 끊김 없이 이어지는가?
- 대시보드로 전환했을 때 네이티브 콘텐츠가 교정 외곽보다 더 멀리
  확장되는가?

공식 소비자 사양의 `640×350` 영역을 플러그인에서 직접 지정하거나
대시보드가 정확히 어떤 해상도로 렌더링되는지는 이번 테스트로 단정하지
않는다.

## 접근 방식

기존 루트 HUD와 진단 경로를 변경하지 않고 `/calibration-max` 전용 경로를
추가한다. 이 경로는 브라우저 Canvas에서 `576×288` 교정 패턴을 직접 그린
뒤, 이미 실제 G2에서 성공한 SDK `0.0.10`의 4타일 이미지 전송 함수를 그대로
사용한다.

별도 이미지 파일이나 의존성은 추가하지 않는다. 교정 패턴을 코드로 그리면
좌표를 테스트할 수 있고 원본 이미지의 축소나 여백이 결과에 섞이지 않는다.

## 교정 패턴

검정 배경 위에 다음 요소를 최대 밝기 신호로 그린다.

1. 좌표 `0`과 최종 좌표 `575`, `287`에 닿는 4픽셀 외곽 띠
2. 외곽에서 8픽셀 들어온 2픽셀 보조 테두리
3. `x=287~288`, `y=143~144`를 덮는 2픽셀 중앙 십자
4. 가로와 세로 방향의 32픽셀 간격 눈금
5. 각 사분면의 `TL`, `TR`, `BL`, `BR` 표식
6. 중앙의 `576×288 MAX` 표식

모든 선은 반 픽셀 안티앨리어싱이 생기지 않도록 정수 좌표의 `fillRect`로
그린다. 문자 표식은 Canvas의 고정폭 글꼴을 사용하되 판정은 문자 모양이
아니라 외곽 띠와 눈금을 기준으로 한다.

## 앱 동작

- `/calibration-max`가 열리면 교정 패턴을 Canvas에 그린다.
- 기존 `transmitCanvas()`가 Canvas를 네 개의 `288×144` PNG로 나눈다.
- `relicTL`, `relicTR`, `relicBL`, `relicBR` 순서로 직렬 전송한다.
- 웹 화면의 상태 문구는 현재 전송 진행과 실패 지점을 그대로 표시한다.
- 기존 `/`, `/diagnostic-v10` 동작과 SDK 버전 계약은 변경하지 않는다.

## 판정 절차

1. Even 앱의 개발자 QR 스캐너로 `/calibration-max` URL을 연다.
2. 네 타일의 전송 완료 상태를 확인한다.
3. 안경을 움직이지 않은 채 외곽 띠, 보조 테두리, 중앙 십자를 관찰한다.
4. G2에서 대시보드로 전환하고 콘텐츠의 가장 바깥쪽 위치와 비교한다.

결과는 다음처럼 해석한다.

| 관찰 | 해석 |
|---|---|
| 대시보드가 교정 외곽 밖까지 보임 | 네이티브 대시보드가 더 넓은 표시 영역을 사용할 가능성이 큼 |
| 양쪽 외곽이 같음 | 기존 차이는 콘텐츠 밀도, 밝기 또는 입체 레이어의 영향일 가능성이 큼 |
| 교정 외곽 일부가 잘림 | 착용 위치나 앱의 화면 높이 설정을 먼저 조정해야 함 |
| 중앙 십자가 끊기거나 어긋남 | 4타일 배치 또는 이미지 전송 경계 문제 |

## 오류 처리

페이지 생성이나 개별 이미지 전송이 실패하면 기존 오류 메시지와 컨테이너
이름을 웹 화면에 표시한다. 실패 시 자동 재시도나 SDK 변경은 하지 않는다.
최초 성공 조건을 보존하기 위해 SDK는 `0.0.10`으로 유지한다.

## 자동 검증

- `/calibration-max`가 교정 모드를 선택하는지 검사한다.
- 교정 함수가 Canvas를 정확히 `576×288`로 설정하는지 검사한다.
- 외곽 띠, 보조 테두리와 중앙 십자의 정수 좌표를 검사한다.
- 교정 모드도 이미지 컨테이너 네 개와 기존 직렬 전송 경로를 사용하는지
  검사한다.
- 전체 Vitest, 타입 검사, 프로덕션 빌드와 사이트 패키징 테스트를 실행한다.

## 완료 조건

- 기존 테스트를 포함한 모든 자동 검증이 통과한다.
- Tailscale URL이 HTTP 200을 반환한다.
- 실제 G2에서 네 타일 전송이 완료된다.
- 사용자가 교정 외곽과 대시보드 외곽의 비교 결과를 알려줄 수 있다.
